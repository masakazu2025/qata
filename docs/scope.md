# いまの段階の範囲：1. 管理の拡張

[roadmap.md](roadmap.md)（中期目標）の段階 1 です。段階が変わったら書き直します。前の段階（PoC）の範囲は、git の履歴と roadmap.md にあります。

## 完了の条件

**電卓のテスト十数本を、タグと有効な版で絞り込んでまとめて流し、進み具合と結果の一覧を web と MCP で見られる。**

## 区切り

段階の中を二つに分け、上から作る。番号は roadmap.md の付録の機能の棚卸しのもの。

| 区切り | 見せられること | 機能 |
| --- | --- | --- |
| 1-1. 探して使い回す | テストケースにタグと有効な版を付け、絞り込み、クローンして使い回せる。人は web で作ったり直したりでき、AI は MCP で探して流用できる | A4・B2〜B7 |
| 1-2. まとめて流す | 選んだテストを続けて流し、進み具合と結果の一覧を web と MCP で見られる。スクショは大きく開いて左右で切り替えられる | C3・D5〜D7 |

## やる

- テストケースの形式に、タグと有効な版（範囲）を足す（契約の変更）
- タグと有効な版での絞り込み・検索（web・MCP）
- クローン（元を記録し、タグを引き継ぎ、元も残す）
- 人が web でテストケースを作る・直す
- AI が MCP でテストケースを探して受け取り、流用する
- 作るときに必須のタグ（何を必須にするかは、1-1 の中で決める）
- 選んだテストを、まとめて続けて流す（契約の変更）
- まとめて流しているときの進み具合と、実行の結果の一覧（web・MCP）
- スクショを大きく開いて、左右で切り替えて見る
- 対象は電卓のまま。操作はキーとタップだけ、確認事項は文字の一致だけ

## やらない

- 手順の表現を広げること（テンプレート・引数・待機・同時押し・制御の構文）：段階 2
- 業務アプリの性質への対応（練習台・立て直し・起動し直さずに流す・文字の読み方）：段階 3
- 運用（予約・中断と再開・複数の端末・動画・インポートとエクスポート・不具合の報告への引用）：段階 4
- server の中から LLM を呼ぶ仕組み（server は LLM を呼ばない）
- 会社の環境（Microsoft 365 Copilot など）との接続
- ルール（rules）を AI が自分で見直して改善する仕組み

「やらない」にあるものに備えた抽象化・フォルダ・コードは作りません。思いついたことは [ideas.md](ideas.md) に書きます。
