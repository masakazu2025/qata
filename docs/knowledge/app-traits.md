# 業務アプリの性質

対象のアプリが持ちうる、テストの自動化に効く性質です。電卓のデモには要らないものも、想定として置きます。

| 性質 | テストへの効き方 | いまの扱い | 出どころ |
| --- | --- | --- | --- |
| 起動し直せない（常駐する） | テストのたびに起動し直して、まっさらな状態から始める、ができない | 毎回起動し直す（電卓のため）。立て直しは [automation-pitfalls.md](automation-pitfalls.md) | D16 |
| 全画面で、表示が複数の画面にまたがる | ウィンドウだけを撮ると、見るべきものが写らない。ウィンドウの大きさをそろえられない | スクショの範囲に「すべての画面」を持つ。大きさは書かない | D15・D16 |
| 古い Windows アプリ | UI Automation で部品や文字が取れるとは限らない | 読み方を足せる形にした。いまは UI Automation だけ | D17 |
| 同時押しを判定する | 修飾キーとの同時押しなど、キーの押し方そのものが仕様になる | 扱わない。キーは 1 文字か名前付きのキーだけ | D13 |
| タッチで操作する | 部品は座標で指すことが多い。画面の大きさや置き方で座標が変わる | タップは座標。座標はウィンドウの外枠の左上が原点の物理ピクセル | D16 |

- qata は、起動し直さない場合にも対応できるようにする。
- ウィンドウを指定せず、全画面でのケースにも対応する。
- 性質を足すときは、[knowledge.md](../../.claude/rules/qata/knowledge.md) に沿い、特定の業務や製品が分からない形で書く。
