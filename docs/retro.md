# 振り返り

周回ごとの振り返りを置きます。新しい周回を上に足します。記録する項目は [process.md](process.md) の「振り返り」に従います。

## 数え方

- **時間**：Claude Code のセッションの記録の、最初と最後の時刻の差。セッションの間の休みは入れない。
- **人の発言**：セッションの記録から、人が打った発言を抜き出し、AI が次の 4 つに分けた。分け方は AI の判断で、目安です。
  - **直した**：AI の進め方・案・ルールを、人が直した。**仕組みが育ったかの指標は、これが減っていくこと。**
  - **決めた**：人が決めるもの（目的・スコープ・対象の業務アプリの前提など）に答えた。AI に聞かれて答えたものも含む。
  - **聞いた**：人が理解するために聞いた（技術の説明など）。
  - **定型**：セッションの開始（「つぎ」）、マージの許可、GitHub のリポジトリの URL。
- 途中で止めた（中断）だけのものは数えない。

### 気づき（AI）

- **直しは、ルールに落とすと止まった。** 同じ指摘が二度出たのは「人に聞きすぎる」だけで、二度目はルール（D21）ではなくスキル（session-end）が古いままだったのが原因。ルールとスキルが食い違っていないかは、いまの関門では捕まらない。
- **人の時間の多くは、技術の説明に使われた。** JSON Schema の説明は 14 往復かかった。結論と例を先に出していれば、短くできたはず。
- **定型の発言は、ほぼマージの許可。** CI と AI のレビュー（[ideas.md](ideas.md) の「次の周回で、先に取り組むもの」）が入れば、ここが減る。リポジトリを作るのは外に出ることなので、人のままでよい。
- 文書と契約の段は「直した」が多いが、ここで決まった前提（対象の業務アプリのこと）が、あとの部品の段で質問を出さずに済んだ理由でもある。

### 人から

- 総評として、出来は予想よりも良かった。AIにできるだけ任せると規定したので、それが有効に機能してくれた
- ルールを持って作る、という部分は形になってきている。
- 他のプロジェクトで流用が効くような、という部分は、まだまだこれから育てる必要が在る
  - コーディング規約
  - フォルダ構成テンプレート（どこまで規定するか？）
  など
- 親において、例えばユースケースなどを追加できていない。今回はひとつの要件で組み立てけど、次回以降、ドキュメントをどう管理するかは課題
- コーディングについては、レビューする力も時間もないため、レビューエージェントを定義しつつ、全部を見ず、要点を持って、レビュー精度を確かめる時間が必要
- 技術要件などもこちらで整えたかったところ。でも、PoCだったので、徐々に詰めながらリファクタリングで、まだ間に合うと考える
