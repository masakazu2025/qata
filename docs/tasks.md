## 次にやること（優先順）

次の周回（2 周目）。デモの完了（本物の電卓）を先にし、土台の直しは最低限にする（D30）。本格的な直しは、デモのあと（[ideas.md](ideas.md) の「デモが終わってから、本格的に取り組むもの」）。

1. **CI を最低限で入れる**　担当：AI
   - 各部品（server・runner・web）のいまのテストを GitHub Actions で回し、ブランチの保護で、通らないとマージできないようにする。
   - 親の契約を読むために、CI では親のリポジトリを丸ごと取ってきて隣に置く。親の場所は環境変数でも指せるようにする（指していなければ、いまどおり `../qata`）。要らないものを外していくのは、デモのあと。
   - AI のレビューはまだ入れない。マージの前の人の一言は続ける。
   - runner は Windows で動くので、CI も Windows の実行環境にする。
2. **Vercel で、デモ版の web を見られるようにする**　担当：AI（qata-web）
   - ビルドのときに `VITE_DEMO=1` を付けると、`main.tsx` が本物の `/api` の代わりに、ブラウザの中の偽の server の `fetch` を渡す（`createApi` は fetch を差し替えられる）。公開先は https://qata-web.vercel.app/ 。
   - 偽の server は、テスト用（Node で契約を確かめる）とブラウザ用（例のデータを読むだけ）に分ける。データは契約の例と電卓のスクショの PNG を web の中に写して持つ（Vercel には隣の `../qata/` がない。D30 の「使うものだけを写す」の最初の一歩）。写したものが契約の例と一致することを、テストで確かめる。
   - 登録 → 承認 → 実行 → スクショを画面で一通り触れること。データはブラウザの中だけで、再読み込みで最初に戻る。デモ版であることを画面に出す。
   - 公開されるので、中身は電卓の例だけにする（D28）。
3. **偽物を本物に置き換え、デモを完了させる**　担当：AI（段取りは、このタスクに入るときに分ける）
   - [process.md](process.md) の「順番」の 3。runner の偽の操作を pywinauto で本物の電卓に置き換え、Claude から MCP で頼むデモを通す。置き換えるたびに、端から端までのテストが通り続けることを関門にする。
   - ここから、関門をすり抜けて、あとで見つかった問題を数える（[retro.md](retro.md)）。
4. **書き方を縛るもの（規約・パターン・雛形）を決める**　担当：AI（案）・人
   - 3 で実際に困ったことから決める（[ideas.md](ideas.md)）。

親と子の関係のルール（A）は、この周回ではやらない。いまの形（D24）のまま。
