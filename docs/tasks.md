# タスク

これからやることを、優先順に並べます。上から順にやります。

- 終わったタスクは消し、やったことは [log.md](log.md) に書きます。
- 一つのタスクは、一つのセッションで終わる大きさにします。大きいものは分けます。
- 「担当」は AI か人。人の判断を待つものは「人の判断待ち」に置きます。

## 次にやること（優先順）

次の周回（3 周目）は、振り返りと QA だけで回す（D34）。2 周目は実装を急いだので、関門をすり抜けたものを探し、関門と書き方の縛りに返す。

1. **2 周目を振り返る**　担当：AI（数字と案）・人
   - [retro.md](retro.md) に、最初の周回と同じ形で足す（時間・人の発言の数・内容）。
2. **QA：触って探す**　担当：AI・人
   - 最初に確かめる：`needs_review`（D18）は手順の側のチェックボックスだが、MCP では AI が埋める。デモでは 3 件のうち 2 件を AI が「要らない」として登録し、承認なしで実行された。AI が自分で人の確認を飛ばせてよいか。
   - わざと崩した手順や、部品の辞書にない言葉で頼み、どこで止まり、どこをすり抜けるかを見る。
   - 見つけたものは、すり抜けとして [retro.md](retro.md) に数え、どの関門を足せば止められたかまで書く。
3. **QA：別の目で見る**　担当：AI
   - テストを書いた文脈とは別の文脈で、テストとコードをレビューする（[ideas.md](ideas.md) の AI のレビューの下見）。
4. **書き方を縛るもの（規約・パターン・雛形）を決める**　担当：AI（案）・人
   - 2・3 で見つかったことから決める（[ideas.md](ideas.md) の「コードの書き方を縛るもの」）。

親と子の関係のルール（A）は、この周回でもやらない。いまの形（D24）のまま。
