## 次にやること（優先順）

次の周回（2 周目）。デモの完了（本物の電卓）を先にし、土台の直しは最低限にする（D30）。本格的な直しは、デモのあと（[ideas.md](ideas.md) の「デモが終わってから、本格的に取り組むもの」）。

1. **偽物を本物に置き換え、デモを完了させる**　担当：AI
   - [process.md](process.md) の「順番」の 3。Claude から MCP で頼むデモを通す。置き換えるたびに、端から端までのテストが通り続けることを関門にする。
   - ここから、関門をすり抜けて、あとで見つかった問題を数える（[retro.md](retro.md)）。
   - 段取り（runner の本物の操作は済み。qata-runner の R3）：
     1. **server：電卓の辞書を本物に合わせる。** 本物の runner で分かったこと：電卓は 336 x 509 より小さくできない（いまの 320 x 500 は `window_size_mismatch` で止まる）。電卓は前に使ったモード（標準・関数電卓）で開くので、タップの座標はモードで変わる。大きさとモードの扱いを決め、本物の runner でタップが当たることを確かめる。契約の例の大きさも合わせる。
     2. **web：端から端までのテストを本物の runner でも回せるようにする。** runner を `QATA_RUNNER_OPERATOR=windows` で立ち上げる切り替え（手元だけ。CI はデスクトップがないので偽物のまま）。
     3. **全体：Claude Code から MCP で頼むデモを通す。** 本物の電卓が動き、web で結果とスクショを見るところまで。人に画面で見てもらう。
2. **書き方を縛るもの（規約・パターン・雛形）を決める**　担当：AI（案）・人
   - 1 で実際に困ったことから決める（[ideas.md](ideas.md)）。
