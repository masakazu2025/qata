# issue の使い方

やることは GitHub の issue に置き、優先順は GitHub Projects のボードで持つ。ボードの場所は、プロジェクトの CLAUDE.md に書く。

## 置き場所

- 一つのリポジトリで閉じるものは、そのリポジトリの issue。
- リポジトリをまたぐものと全体の判断は、親のリポジトリの issue（`parent-and-children.md`）。
- ボードの項目は、必ず issue として作る。リポジトリに属さない下書きの項目は使わない。

## issue にするもの

- やると決めて、終わりの条件が書けて、すぐ手をつけられるものだけ。まだ決めていないものは `docs/ideas.md` に置く。issue に上げたら、ideas.md からは消す。
- AI は issue を自分の判断で立てない。立てるのは、人がやると決めたときと、親が結論を出したときだけ。作業の中で見つけたことは、pull request の説明か ideas.md に書く。
- 一つの issue は、一つのセッションで終わる大きさにする。大きいものは sub-issue に分ける。
- 本文は雛形（背景・やること・終わりの条件・関連）に沿って書く。
- 経緯を知らない人が、出先で issue だけを読んでも分かるように書く。
  - タイトルだけで、何をするかが分かるようにする（動詞で終える）。
  - 背景には、なぜやるのか（何が困っていて、やると何がよくなるか）を書く。
  - 内輪の言葉や番号（決めたことの番号など）を、説明なしで使わない。一言添えるか、関連にリンクで置く。
- 立てた issue は、ボードに足して列を決める（決めてもらっていなければ Backlog）。

## ボードの列

| 列 | 意味 |
| --- | --- |
| Backlog | 着手できるが、いまはやらない |
| Next | 次にやる。AI が取ってよいのはここだけ。上から順 |
| In progress | 作業中（ブランチ・pull request がある） |
| Done | 終わった |

## ラベルと担当

- `background`：裏で回してよい。人が使っている画面を操作しない。
- `needs-desktop`：人が使っている画面を操作する。人が PC を使っていないときだけ。
- ほかのラベルは、困ってから足す。優先度のラベルは作らない（優先順はボードの並び）。
- 人の番のもの（人の判断・確認）は、人を担当（assignee）にする。AI は担当が人の issue を進めない。

## 進め方

- 着手したら、issue を In progress にし、`git.md` に沿ってブランチを切る。
- pull request の説明に、やったことと `Closes #番号`（別のリポジトリの issue なら `owner/repo#番号`）を書く。やったことの記録は pull request に残す。
- 月に一度、動いていない issue を AI が一覧にし、閉じる候補を出す。閉じるかは人が決める。
