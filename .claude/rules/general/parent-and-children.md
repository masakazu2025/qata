# 親と子のリポジトリ

一つのプロジェクトを、親のリポジトリ（目的・スコープ・契約・共通の決まり）と、子のリポジトリ（部品）に分けているときの決まり。

## 子は親を参照する

- 考え方や共通の決まり（ルール・スキル・契約）は、親のものを参照する。子に写さない。
- 子には、その部品だけの決まりを置く。

## 全体に関わることは、親に上げて親が決める

子の作業の中で、ほかの部品や全体に関わることが見つかったら、子の中で決めずに親に上げる。結論は親が出す。

| 種類 | 中身 | 上げる先 | 親での扱い |
| --- | --- | --- | --- |
| issue | やると決めたこと・いま困っている問題 | 親のリポジトリの GitHub の issue | ボードの並び順で扱う。困っている問題は Next の先頭に置く |
| idea | 次回以降の改善案。いまの作業は止まらない | 親の `docs/ideas.md` | 次の周回の計画のときに検討する |

- 上げるときは、どの子から、何をしていて見つかったかを一行で添える。
- 結論が出るまで、子は全体に関わる部分に手を入れない。待っている間は、子の中で進められるタスクをやる。
- 親が結論を出したら、`docs/decisions.md` に残し、関わる子のリポジトリに issue を立てる。
- その子の中だけで閉じる問題や改善案は、子の issue か `docs/ideas.md` に置く。親には上げない。
