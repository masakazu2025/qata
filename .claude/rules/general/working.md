# 作業の進め方

- **管理するのは個々の課題ではなく、関門。** テスト、依存の向きの検査、契約との一致など、機械で確かめられる関門を通ったものは、途中経過を問わない。
- **分割は境目（データの形）で切る。** 各タスクは、他の部品を知らなくても作れて、完了を機械的に確かめられる大きさにする。
- **一セッションは、テストが通る状態で終わる一歩。** やることは GitHub の issue に持ち、やったことは pull request に残す（`issues.md`）。
- **YAGNI。** 今のスコープにないものに備えた抽象化・分割はしない。中身のない層やフォルダは作らない。
- **二つを同時にやらない。** 途中で別の直したいものが出たら、手を出さずに `docs/ideas.md` に書く。
- 文書は日本語で書く。
