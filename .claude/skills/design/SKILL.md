# 設計

判断の型。下の基準で、変える場所と形を決める。

## 入力

- 要件の確認（`requirements`）で作った、終わりの条件と確かめ方の表
- 変えるリポジトリのいまの構成と、関わる契約

## 基準

| 基準 | 見ること | 引っかかったら |
| --- | --- | --- |
| 境目で切る | 変える部分の入り口と出口が、データの形で言えるか | データの形を先に決める（`.claude/rules/general/working.md`） |
| 契約 | 部品の間のデータの形を変えるか | 契約は正の置き場所で変える。確定させるときは人に聞く（`.claude/rules/general/autonomy.md`） |
| 正から作ったもの | 変える正（契約など）から、ほかのリポジトリが生成したり写したりしているものがあるか。説明の文だけの変更でも | それも直す。複数のリポジトリにまたがるときの進め方は `.claude/rules/general/git.md`（暫定。本来は、読む側が正の更新を見て自分で追いつく） |
| 依存の向き | 決まった依存の向きを崩さないか | 崩さない形に変える。崩すしかないなら、それは構造の変更として扱う |
| 構造 | フォルダ・部品・層が増えたり、分かれたりするか | この先の構想に関わるなら、影響を図にし、案とおすすめを付けて人に聞く。関わらないなら自分で決める |
| YAGNI | いまの終わりの条件に要らないものを作っていないか | 削る。思いついたものは `docs/ideas.md` に書く |

## 出すもの

- 変えるファイルと、それぞれがどの終わりの条件のためか
- 新しく決めるデータの形（あれば）
- 構造や流れが変わるときは、Mermaid の図
- 自分で決めたことは、理由と一緒に `docs/decisions.md` に残す（session-end でまとめて足してもよい）

## 終わりの関門

- 変えるファイルが並んでいて、どの終わりの条件にもつながらないものがない。
- 人に確かめると決めたもの（契約の確定・構想に関わる構造）が、確かめ済みになっている。
