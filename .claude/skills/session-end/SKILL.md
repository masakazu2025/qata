# セッションの終わり

1. 関門を通す。テストや検査があるリポジトリでは、すべて通ることを確かめる。通らなければ、通るまで直すか、手を入れる前の状態に戻す。
2. このセッションで自分で決めたことを、`docs/decisions.md` の上に足す（決めた人：AI、レビュー：未）。
3. 途中で出てきた、今のスコープの外の思いつきを `docs/ideas.md` に書く。子のリポジトリで、全体に関わる issue や idea が出たときは、親に上げる（`.claude/rules/general/parent-and-children.md`）。
4. 知識の層（親の `docs/knowledge/`）があるプロジェクトでは、このセッションで人から出た知識（対象の前提・業務アプリの性質・言葉の意味）を、一般化して書く。書き方はプロジェクトのルールに従う。新しく使い始めた言葉は用語集に足す。
5. `.claude/rules/general/git.md` に沿ってコミットし、ブランチを push して pull request を作る。説明には、やったこと・作業の中で見つけたやるべきこと・`Closes #番号` を書く（`.claude/rules/general/issues.md`）。人の判断を待つものがあれば、その issue の担当を人にする。
6. 人への報告では、やったことと、人に聞くこと（あれば）だけを伝える。聞くのは `.claude/rules/general/autonomy.md` で人に聞くと決めたものだけで、質問の出し方もそこに従う。あとから変えられる、AI が決めたことは、レビューを頼まない。`docs/decisions.md` に「レビュー：未（人のレビューは要らない）」で残し、PoC が終わったときにまとめて振り返る。
