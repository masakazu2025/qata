# セッションの終わり

1. 関門を通す。テストや検査があるリポジトリでは、すべて通ることを確かめる。通らなければ、通るまで直すか、手を入れる前の状態に戻す。
2. `docs/tasks.md` を更新する。
   - 終わったタスクを消す。
   - 作業の中で見つかった、やるべきことを足し、優先順を見直す。
   - 人の判断を待つものは「人の判断待ち」に移す。
3. このセッションで自分で決めたことを、`docs/decisions.md` の上に足す（決めた人：AI、レビュー：未）。
4. 途中で出てきた、今のスコープの外の思いつきを `docs/ideas.md` に書く。子のリポジトリで、全体に関わる issue や idea が出たときは、親に上げる（`.claude/rules/general/parent-and-children.md`）。
5. 知識の層（親の `docs/knowledge/`）があるプロジェクトでは、このセッションで人から出た知識（対象の前提・業務アプリの性質・言葉の意味）を、一般化して書く。書き方はプロジェクトのルールに従う。新しく使い始めた言葉は用語集に足す。
6. `docs/log.md` のいちばん上に「日付：やったこと」を一行足す。
7. `.claude/rules/general/git.md` に沿って、コミットし、ブランチを push して pull request を作り、マージする。
8. 人への報告では、やったことと、人に聞くこと（あれば）だけを伝える。聞くのは `.claude/rules/general/autonomy.md` で人に聞くと決めたものだけで、質問の出し方もそこに従う。あとから変えられる、AI が決めたことは、レビューを頼まない。`docs/decisions.md` に「レビュー：未（人のレビューは要らない）」で残し、PoC が終わったときにまとめて振り返る。
