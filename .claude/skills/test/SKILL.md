# テスト

手順型。次の順で進める。

## 入力

- 終わりの条件と確かめ方の表
- 実装（`implement`）の結果

## 手順

1. リポジトリの関門を、手を入れていない状態から通し直す（キャッシュや手元の状態に頼らない）。
2. 端から端までのテストがあるリポジトリでは、それも通す。ただし、説明の文だけの変更（動きもデータの形も変わらない）なら回さない。回さなかったことは、結果の表に書く。
3. 終わりの条件を表の上から一つずつ、確かめ方で確かめる。結果を表に書く：確かめた／確かめられなかった（理由）。
4. 目で見る確かめ方のものは、見た場所（画面・ファイル・コマンドの出力）を書く。人が使っている画面を操作するものは、`needs-desktop` の決まりに従う（`.claude/rules/general/issues.md`）。
5. 確かめられなかったものがあれば、直せるものは実装に戻る。直せないものは、そのまま pull request の説明に残す。

## 出すもの

- 結果を書いた、終わりの条件と確かめ方の表（pull request の説明に写す）

## 終わりの関門

- 終わりの条件のすべてが「確かめた」か、「確かめられなかった（理由）」になっている。
- リポジトリの関門がすべて通る。
