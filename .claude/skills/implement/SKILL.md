# 実装

手順型。次の順で進める。

## 入力

- 設計（`design`）で決めた、変えるファイルとデータの形
- 終わりの条件と確かめ方の表

## 手順

1. 確かめ方がテストのものから、テストを書く。動かして、失敗することを見る。
2. テストが通る最小のものを書く。
3. リポジトリの関門（テスト・lint・依存の向きの検査・型の生成と契約の一致など）をすべて通す。通らなければ 2 に戻る。
4. まとまりごとにコミットする（`.claude/rules/general/git.md`）。
5. 終わりの条件の数だけ、1〜4 を繰り返す。
6. 途中で別の直したいものが出たら、手を出さずに `docs/ideas.md` に書く。

文書やルールだけを変えるときは、1 のテストの代わりに、確かめ方（リンク先があるか、重なって書いていないかなど）を手元で確かめる。

## 出すもの

- コードとテスト、またはそれに当たる文書
- コミット

## 終わりの関門

- リポジトリの関門がすべて通る。
- 確かめ方がテストのものは、すべてテストがある。
