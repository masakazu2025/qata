# 要件の確認

判断の型。決まった手順ではなく、下の観点で issue を読む。

## 入力

- issue の本文とコメント
- `docs/scope.md`
- issue が触れる契約や文書

## 観点

| 観点 | 見ること | 引っかかったら |
| --- | --- | --- |
| スコープ | `docs/scope.md` の「やる」に入っているか | 入っていなければ止めて人に聞く |
| 確かめられるか | 終わりの条件の一つずつに、テスト・検査・目で見るのどれかで確かめる方法があるか | 確かめ方を決めて書く。決められなければ条件を言い換える |
| 人しか知らない前提 | 対象や将来の使われ方について、仮に置いた前提があるか | `.claude/rules/general/autonomy.md` に沿って聞く。答えがなくても進められるなら、仮に決めて `docs/decisions.md` に残す |
| 大きさ | 一つのセッションで終わるか、二つのことが混ざっていないか | sub-issue に分ける（`.claude/rules/general/issues.md`） |
| 書かれていないこと | 本文に書かれていないが、やらないと終わらないことがあるか | 終わりの条件に足すか、やらないと決めて書く |

## 出すもの

終わりの条件と確かめ方の表。作業の間は手元に持ち、最後に pull request の説明に写す。

| 終わりの条件 | 確かめ方 |
| --- | --- |
| （issue の条件をそのまま） | （テストの名前・検査のコマンド・目で見る場所） |

## 終わりの関門

- 終わりの条件のすべてに、確かめ方が一つ付いている。
- 人に聞くことが残っていない。残っていれば、答えを待つ間にできる工程だけ進める。
